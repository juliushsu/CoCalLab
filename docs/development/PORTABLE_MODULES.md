# 可移植 OCR／AI／檔案模組開發規範

CTO 指示：2026-11-02。適用後續新增能力，供財務、影視會計、人資、碳盤查等產品各自使用。
目前 Upload-N1／N2 與本機整合優先完成；本次只記錄規範，不搬動現有程式、建立新平台、啟用 provider 或增加費用。

## 執行與依賴邊界

共用交付是程式碼：各產品以自己的程序、設定、憑證及基礎設施獨立執行。
外部 OCR／AI 由各產品自行配置供應商 adapter，不經由中央共用 API。
核心只依賴明確的輸入／輸出介面；CoCalLab UI、資料表、碳盤查規則、商業欄位及人工核准都留在產品 adapter／應用層。

供應商與檔案儲存 adapter 應可替換。核心不得寫死專案 URL、表名、客戶、bucket、租戶、API key 或部署位置。
設定範例只用明示 placeholder 或本機合成值；憑證由各產品安全注入，不隨模組發佈。

## 第一個案例的可測介面

先選一個已授權、可真正執行的使用案例。以獨立模組目錄（例如 `modules/<capability>/`）交付、記錄模組版本與介面；不為尚未接用的產品搭大型框架。
第二產品接用時，以兩邊的實際 adapter 需求抽出版本化 package；各產品自行釘選／升級版本，模組更新不得自動部署或修改其他產品資料。

OCR 輸出至少保留：

| 類別 | 介面需求 |
| --- | --- |
| 原始內容 | 原始文字；逐頁／區塊內容；原始表格、列／欄及儲存格，不只回傳產品想要的欄位 |
| 位置 | 頁碼、座標／bounding box；明訂座標原點、單位／正規化方式與頁面大小，未提供則明示缺少 |
| 可信度 | 頁／區塊／儲存格可用的 confidence 及其語意／尺度；供應商未提供時用缺少狀態，不假造分數 |
| 來源 | 呼叫端提供的檔案來源識別、處理時間、來源引用與可追溯的內容識別，避免將本機路徑或企業資料公開 |
| 版本 | provider、model／engine、provider API／模型版本及 adapter／輸出介面版本；未知版本明示 UNKNOWN |

發票欄位、會計科目、碳排範疇、薪資／人資判讀、人工核准與最終寫入都由產品端處理。
OCR 成功不等於業務資料正確或已批准。provider 不可用、超時、額度、拒絕、部分輸出與解析錯誤均須可測，不得用 mock 補正式成功。

## 資料與恢復邊界

快取 key、暫存檔、儲存位置、批次工作及恢復紀錄均由產品端提供 scope，至少保留產品／租戶邊界及必要的使用者／工作識別。
核心不能自選第一個租戶、共用預設 bucket 或從 UI／JWT 自稱角色推定授權。
adapter 執行實際讀寫時重新驗證各產品的權限；UI 前置檢查不能取代服務端控制。

模組的範例 cache／storage adapter 不可默認寫入中央服務。
恢復介面需明確區分原始物件、處理 attempt 與業務紀錄，描述哪些重試可用原 ID、哪些可能重複、哪些需人工確認。
不得因一產品清理／升級而清除其他產品或租戶的檔案、快取或 journal。

## 最低交付內容

每個獨立模組／版本化 package 應含：

1. 可執行的程式碼、版本與授權／必要依賴清單，說明執行環境及安裝方式。
2. 輸入、輸出、錯誤、取消／逾時與重試語意的明確介面；provider／storage adapter 的替換位置。
3. 去敏設定範例、最小使用案例與合成 fixture；實際 provider 實測另記版本、環境及未驗範圍。
4. 有意義的成功、失敗、部分結果、隔離／權限與恢復測試；與供應商／真實資料的測試界線。
5. 移植步驟、產品 adapter 範例、相容性與版本升級／回復說明；無跨產品連動部署。
6. 費用、資料外送與權限需求的具體申請材料。未獲授權時只暫停相關接入，其餘本機工作繼續。

## 移交與逐步接入

接收 Mac、Readdy 或 Mac Codex 成果時，先保留來源存檔／Git ref、實際 SHA、未提交 diff、未追蹤檔案與來源清單。
不要帶入憑證或正式資料，不以覆蓋本機方式消除差異。
先驗證一個現有可用流程，再逐項接入 adapter；可用程式沿用，未完成功能如實標示。
