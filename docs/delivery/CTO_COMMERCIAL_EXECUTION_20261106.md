## 不可越過的邊界
不得自行合併 main、部署 Production、建立雲端資源或帳號、改雲端 schema/RLS/資料、使用真實企業資料、增加費用或送資料到外部 AI。這些須 Owner 明確核准具體環境、操作與成本。
本機可開發 migration 並在隔離測試庫驗證，不代表可以套到雲端。
不重試已知不支援的 Docker/WSL 路徑，不連既有 5432。
正式功能不得以 Mock 回退、假成功或固定數字掩蓋未實作。合成環境可使用完整 fixtures，但需持續標示。
保留既有前後台入口、選單、篩選、來源鏈及已完成修復。需要移除或改變業務功能時先提交差異與理由給 CTO；不得默默刪功能來讓測試過關。
共用模組是可移植程式碼：各產品獨立資料、設定、憑證與部署；依既有 PORTABLE_MODULES.md 使用 adapter。先完成真實用途，再抽取必要模組，不建中央共用 API 平台。

## 連續工作順序
以下是工作佇列，不代表功能已缺失；先讀來源與證據，已有可靠成果就引用並跳過。每次只主導一個可驗收成果。

| 順序 | 交付 | 完成檢核 |
| --- | --- | --- |
| M1 立即 | 原產品介面人工活動建檔 → 計算 → 保存／重讀報告快照 | 沿現有正常入口與正式 handler；明確單位、係數來源與版本、期間、Scope、取捨及錯誤；重載後保存結果一致；不能靠測試專用 INSERT 或 lab 頁面代替產品功能 |
| M2 | 補齊可操作預覽與功能保留檢核 | 原 App 前後台主要入口可操作；A/B/shared 角色、活動/草稿/計算/報告、空資料/失敗/跨租戶拒絕案例齊備；每次功能變更交付入口、操作步驟及截圖，寫清楚合成與未驗範圍 |
| M3 | 正式報告一致性與附件可信度 | 檢查正式 handler 快照建立與後續更新的原子性／冪等性；處理伺服器 hash 驗證、收件偽造與刪除部分失敗。先以實際缺口拆小票，保留稽核來源；不可因前端 hash 或替身測試就宣稱可信 |
| M4 | 正式非 Mock 文件 → 人工轉錄草稿 → 審核 → 活動 | 先提出沿現有欄位的最小契約給 CTO：來源文件、轉錄者、單位、期間、係數選擇、Scope 與人工確認責任；核准後實作。OCR 可維持明示未完成，人工轉錄不得冒稱 OCR；真實 AI 串接另列成本／資料傳送決策 |
| M5 | 已授權隔離環境真實驗收 | Owner 指定環境及可操作範圍後，才做真實 Auth/JWT/RPC/Storage、migration、備份／復原及瀏覽器 E2E；未授權時保持 NOT_RUN，繼續不依賴該環境的工作 |
| M6 | 商用候選與業務驗收 | 固定整合 SHA、完整功能清單、租戶權限矩陣、實測證據、已知限制、復原方案、營運與成本資料；Owner 驗收核心業務與上線方案後，才另行核准發布 |

M1 驗收要點：
- 先核對目前 NEXT_ACTION 指定的人工活動入口及計算／快照契約，修復真正的產品缺口。
- 驗證已知案例：100 kWh × 合成係數 0.5 kgCO₂e/kWh = 50 kgCO₂e = 0.05 tCO₂e；係數必須明示為測試資料，不能成為正式預設係數。
- 同時涵蓋未知係數、無權限、保存失敗、重送與重讀；無法計算時明示原因，不能補零或假成功。
- 若既有 Scope 定義不清，標示待確認並提出具體案例給 CTO，不自行決定商業碳盤查規則。

M5 必測租戶矩陣：
- A、B 互相不可讀寫；shared 使用者在 A 管理、B 唯讀；未登入、停權／撤權、過期登入、跨專案及不一致 organization/project。
- 覆蓋 UI、直接 API、RLS、RPC、Storage 原始附件、匯出、報告、日誌及快取；不可只靠隱藏選單。
- 組織切換與撤權時測試進行中的請求、舊分頁、下載與快取；資料不能殘留給下一個使用者。
- 記錄實際 SHA、環境、身份／角色、操作、預期、結果與未驗範圍。任何越權讀寫為阻擋發布問題。
- 不以此清單通過推論永遠不會外洩；結果限受測版本與環境。

## 每項工作的循環
1. 讀 NEXT_ACTION 與相關來源；確認起點和驗收條件。
2. 小範圍實作、保留現有功能；可用 1–2 名代理做不重疊實作或獨立審查，避免多人同改同檔。
3. 執行與變更相符的測試及必要 CI；通過後不為增加數字反覆重跑。測試子集不得重複加總。
4. 修復實際失敗，提交可審查 PR；每份證據固定 SHA。合成、來源、真實環境驗證分開。
5. 更新 docs/delivery/NEXT_ACTION.md 與此佇列的進度紀錄，接下一個 READY 項目；一般進度不等 Owner 逐次批准。
6. 若同一路徑兩次嘗試沒有新證據，停止該路徑、記錄原因並換不受影響的工作。session 結束先保存進度；不得宣稱無限背景執行。

使用 READY / RUNNING / WAITING_CTO / WAITING_OWNER / BLOCKED / SOURCE_DONE / ENV_VERIFIED。
SOURCE_DONE 只表示來源與指定測試通過；ENV_VERIFIED 限具名環境，不代表商用放行。

每次交付或阻礙以以下格式回報：
- 目前目標與狀態：

- 通過證據（測試層級、環境、是否獨立驗證）：
- 未驗證、缺口及已知風險：

## 何時找 CTO、何時停下問 Owner
CTO：契約／架構取捨、資料語意、Scope 定義、跨產品抽取、審查爭議、安全修復方案或需要調整工作順序。提出最小方案、替代方案、證據與建議，停受影響工作，其他 READY 工作繼續。
Owner：雲端環境與資料用途、付費／外部資料傳送、業務規則與責任、接受剩餘風險、main 合併及 Production 發布。須先備妥可審查方案，再問具體選擇；不得把沒有回覆當同意。
有新的越權、資料外洩或破壞性問題，立即保留去敏證據並停受影響流程，不得為了完成里程碑繞過。
一般低風險程式缺陷自行修復與驗證；不為每個 P3 重啟完整紅隊。權限、信任邊界或重大資料流程改動，再請獨立審查；需要 Claude 時準備固定 SHA 的定向問題交 Owner 協調。
