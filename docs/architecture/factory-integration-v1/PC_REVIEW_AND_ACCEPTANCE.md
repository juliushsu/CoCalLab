# PC 端檢核、實作與驗收交接

日期：2026-11-12。狀態：文件已備妥、PC 檢核待執行。文件上傳與 PC 接收／啟動是不同狀態；沒有回執或命令證據，不標記 ACKNOWLEDGED／RUNNING。

## 1. 接手指令

先讀 [設計提案](README.md)及 [API 草案](API_CONTRACT.md)，核對 `juliushsu/CoCalLab` 目前 main／本文件 PR head，並保留本機未提交修改。文件基準為 `94d01b9c9f081df494f805b41166599ccd73541e`；若已有新程式，只檢查新增差異，更新 G01–G07 結論，不重做全案稽核。

這次委託先完成設計交接。PC 評估後，把此工作加入既有系統實作佇列，繼續完成可驗收功能；不要把文件完成當作功能完成，也不要讓本提案阻擋無關的既有 bug fix。若既有 handover PR／開工文件可用，沿用它們的已確認進度；本提案不宣稱那些分支已合併或 PC 已開始執行。

本機可先做明確且可逆的契約、純函式、UI 與隔離 DB 驗證。真實廠商連線需確認資料授權、環境和 credential 範圍；正式資料變更與發布沿用專案既有 owner 決策流程。缺少真實連線不阻擋合成資料的本機閉環。

## 2. 首次檢核清單

- [ ] 記錄實際 branch／HEAD／未提交變更；確認適用的 AGENTS、AI_COLLABORATION 與 canonical docs。
- [ ] 用當前 migrations／services／frontend 對照 G01–G07，逐項記為 EXISTING／PARTIAL／MISSING 並附檔案與 SHA；部署狀態另列 UNVERIFIED。
- [ ] 釐清 `sites` 與舊 `organization_sites` 提案，確認現有 migration 是否只存在檔案或已在隔離環境套用；不建立重複廠區模型。
- [ ] 定稿工單／批次拆併、設備／儀表有效對應、料號／產品版本、實際耗用與 BOM fallback 契約。
- [ ] 確認來源真實權限與 workspace／site 一致性、機器與人工角色、修正／覆核／報告版本規則。
- [ ] 記錄 HMS 名稱、試辦資料權威來源、量測粒度、容差、產品單位與邊界；未定事項寫為假設，不捏造客戶回答。
- [ ] 僅完成本批必要的 test／typecheck／build／lint 基線，歷史通過結果不當作本次結果。

檢核輸出：一份簡短 `PC_REVIEW_RESULT.md`（在後續實作分支新增），列出同意／調整／暫緩的條款、理由、當前 SHA、下一個可交付批次與 blocker。沒有阻礙的項目繼續實作，不停在規劃。

## 3. 分批實作與出口

| 批次 | 可審閱交付 | 完成出口 |
| --- | --- | --- |
| F0 契約評估 | 上述 PC review result、定稿物件／DTO／精度／狀態、差異與依賴 | G01–G07 已有證據；可明確指出可重用及須新增部分 |
| F1 匯入與對應 | 合成 CSV、共用 validation、source record／job、mapping、idempotency／revision、隔離 DB migration | 可匯入／重試／補傳／修正並持久化；錯列可查；權限拒絕有效 |
| F2 生產能源核對 | 工單／批次／設備／能源關聯、總分表／帳單／入庫核對、差異覆核 | 時段、單位、缺漏與差異可見；同一耗用不重算 |
| F3 製造階段產品排放 | 直接歸屬／共用分攤、因子適用性、批次／每單位結果與 lineage | 分配守恆；缺值不變零；所有輸入與版本可追溯 |
| F4 UI 與報告 | 資料來源／對應／差異／批次結果、immutable snapshot、錯誤與缺口文案 | 從結果可回來源；修正後新版本，舊報告 hash 不變；不出現假完成 |
| F5 廠商 pilot | 一家經授權的實際 MES／ERP／EMS adapter、同步排程與補傳、代表使用者驗收 | 以該廠實際資料驗證權威來源與核對；本機測試與真實 pilot 證據分列 |
| F6 CFP 與整體整合 | 依已確認邊界納入其餘生命週期階段；與既有採購／AI／報告／營運佇列整合 | 個別功能與整體商業驗收分開；未滿足範圍不宣稱完整 CFP 或整個系統完成 |

每批一個小 PR，先沿用既有可用邏輯。schema 採 additive／相容演進並在隔離資料庫驗證；不能因新增產品視角改壞組織盤查。測試需驗證行為，不以 mock 畫面或固定假數據作 REAL 證據。

## 4. 最小驗收案例

下列全部為待實作／待執行，初始狀態 **NOT_RUN**。數字與係數僅為合成測試，無官方係數意義。

| ID | 情境 | 必要斷言／可見結果 |
| --- | --- | --- |
| T01 | 同 request key 同內容重試；同 key 異內容 | 前者同 job／無重複活動；後者 409 且無寫入 |
| T02 | 同 record revision 重送、較新修正、舊版晚到、void | replay 不重寫；新版成目前版；舊版不能覆蓋；撤回保留歷史 |
| T03 | 有效／缺少／過期 mapping 與跨 workspace reference | 有效者對應正確；其餘拒絕或待處理；不能進正式計算 |
| T04 | UTC 與 +08:00 同一時段、跨日、邊界相接 | 正規化後一致；`[start,end)` 邊界不重複歸屬 |
| T05 | 累積表 reset、缺讀值、倍率變更、kW 當 kWh | 不產生負耗能或假精確切分；單位不相容拒絕並說明 |
| T06 | 帳單 1,000 kWh、同源總表 1,000、分表 600／300 | 耗用池為 1,000 而非 2,900；保留 100 未對應／損耗待核對 |
| T07 | MES 完工與 ERP 入庫跨期，含 WIP／報廢／重工 | 能說明差異；計畫量不當實際量；重工不重複增加良品 |
| T08 | 相同來源或不同 connection 代表同一耗用 | API 去重之外亦檢查 source lineage；相同來源不算獨立核對證據 |
| T09 | 容差內、超容差、基準零、缺第二來源 | 狀態分別正確；不除零；缺資料不標 within_tolerance；例外有覆核紀錄 |
| T10 | 能源池 1,000 kWh，A 直接 400、B 直接 300，共用 300；合成分攤 A:B=2:1 | A=600、B=400 kWh、未分配=0；直接量未再次共用分攤，總和=1,000 |
| T11 | T10 使用合成係數 0.5 kgCO2e/kWh；A 良品 100 件、B 良品 50 件 | A=300 kg、3 kg/件；B=200 kg、4 kg/件；製造能源總量=500 kg，組織視角不再加產品分配的 500 kg |
| T12 | 零產出、無適用因子、缺耗用、未分配量、副產品 | 總量／缺口保留，單位值必要時為 null；分母及副產品方法明示；不假稱完整 CFP |
| T13 | 同活動有直接排放量測及係數推估；同物料有 supplier PCF／一般因子 | 涵蓋範圍重疊時不重複相加，採用模式與原因可追溯 |
| T14 | 領退料修正、BOM 版本異動、實際耗用補齊 | 新 revision／結果版本；實際值與 BOM 估算不相加；舊版仍可重現 |
| T15 | 來源、mapping、因子或分攤規則更新後重新計算 | 產生新版；舊報告 payload／hash 不變；新舊結果可查來源與差異 |
| T16 | 部分列失敗、收件中斷、逾時重試、並行 worker | job 明細／計數正確；單筆原子一致；無重複 promotion；可安全補傳 |
| T17 | 無認證、撤銷 credential、跨租戶讀寫、超範圍 feed、非授權覆核 | 拒絕且無寫入／資料洩露；connector 無人工核准權；UI 與 API 一致 |
| T18 | 製造階段完成但其他 CFP 階段未齊；UI 收件／核對／完成狀態 | 標示實際邊界與缺口；不顯示正式查證或完整 CFP 成功；錯誤無 silent mock fallback |

## 5. PC 回報格式與完成定義

每批回報：branch／commit SHA、改變的可用行為、G/T 對應、實際執行命令與 PASS/FAIL/NOT_RUN、持久化／UI 證據、尚未驗證範圍、migration／回復方式、blocker 與下一步。公開回報不得包含 secret、企業原始資料或本機敏感路徑。

首輪最小成功是 F1–F4 在隔離環境跑通一個可追溯的案例，並附驗收證據；F5 完成才可宣稱指定廠商已串接，F6 依明定邊界驗收後才可提升 CFP 能力聲明。文件 PR 上傳、PR 合併、schema 存在、測試通過、真實 pilot 與正式部署須分別記錄。
